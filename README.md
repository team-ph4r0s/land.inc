# land.inc

**Живой офис для AI-агентов: видно, кто чем занят, кому нужна помощь и как продвигается задача.**

land.inc превращает локальные сессии Claude Code, Codex и Antigravity в сотрудников изометрического 2.5D-офиса. Они пишут код за столами, читают в архиве, запускают команды в серверной и уходят на кухню после завершения хода. За каждым персонажем стоят события реальной сессии.

Из этого же интерфейса можно поручить агенту задачу в папке проекта, продолжить разговор или собрать команду из разных провайдеров: **планировщик → исполнитель → проверяющий → доработка**.

Проект находится на стадии локального прототипа. Основной сценарий — работа на своём компьютере; интеграция с Antigravity экспериментальная.

## Зачем это нужно

Когда несколько агентов работают в разных окнах и репозиториях, за ними трудно следить. land.inc собирает их в одном месте:

- **Общий обзор.** Активные сессии сгруппированы по проектам; видны действие, модель и ожидание пользователя.
- **Контекст по клику.** Выбор сотрудника открывает журнал его последних действий. Сабагенты связаны с родительской сессией.
- **Доска задач.** Выбор проекта, исполнителя, модели, уровня рассуждений и доступа; результат и продолжение — в карточке задачи.
- **Совместная работа.** Последовательные ходы агентов с передачей результатов, проверкой и финальной доработкой. Ход команды виден в «Переговорке».
- **Наглядные статусы.** Зоны офиса, персонажи и эмоции помогают заметить работу, ожидание и результат тестов.

Для наблюдения не нужны API-ключи: демон читает локальные журналы существующих сессий. Запуск задач с доски использует установленные CLI, их авторизацию и лимиты; это реальные обращения к моделям.

## Быстрый старт

Нужны **Node.js 24+** и npm. Для реальных задач также нужен установленный и авторизованный CLI выбранного агента.

```bash
npm ci
npm run dev
```

Откройте [офис в браузере](http://127.0.0.1:5173). Демон и клиент запускаются вместе; Ctrl+C останавливает их.

**В Windows:** можно дважды щёлкнуть `Открыть офис.cmd` в корне проекта. При первом запуске он установит зависимости, откроет браузер и запустит офис. Окно запуска нужно оставить открытым.

### Показать коллегам за несколько минут

1. Запустите `npm run dev:demo` и откройте офис. Демонстрационные сотрудники пройдут по зонам, даже если реальные агенты сейчас не работают.
2. Выберите персонажа, покажите журнал действий, группировку по проектам и управление камерой.
3. Откройте «Задачи»: покажите выбор папки, исполнителя и доступа. При наличии настроенного CLI можно поручить ему: «Изучи структуру проекта и кратко объясни, как его запустить. Не меняй файлы».
4. Покажите «Совместную работу» и «Переговорку»: где задаются роли и как отслеживаются ходы команды.

`dev:demo` добавляет искусственных сотрудников, но сохраняет наблюдение за реальными сессиями и обычный запуск задач с доски. Демонстрационные персонажи сами модели не вызывают.

Для демонстрации **доски задач без вызовов моделей и чтения реальных сессий** запустите в двух терминалах вместо `npm run dev`:

```bash
# Терминал 1: демон с фейковыми исполнителями
npm run start -w @land/daemon -- --fake-agents --no-real
```

```bash
# Терминал 2: интерфейс
npm run office
```

Фейковые задачи выполняются с задержкой около 6 секунд, их сотрудники появляются в офисе, история задач и команд не сохраняется.

## Как читать офис

**Сессия — сотрудник, проект — ряд столов, действие — место в офисе.**

| Что делает агент | Где это видно |
|---|---|
| Думает или пишет код | За своим столом |
| Читает файлы и ищет по проекту | В архиве |
| Запускает команды и тесты | В серверной |
| Ищет в сети | У интернет-киосков |
| Планирует | У доски планов |
| Делегирует или передаёт ход | В переговорной |
| Ждёт разрешения или ответа | За столом с поднятой рукой и «!» |
| Завершил ход | На кухне, затем уходит домой |

Внешность персонажа зависит от модели: например, у Opus корона, у Sonnet берет, у GPT Sol блокнот, у Antigravity — орбита со спутником. Модель и уровень рассуждений показываются, когда доступны в источнике. Смена модели в сессии отражается в офисе.

Клик по сотруднику или строке списка открывает журнал. Камера перемещается перетаскиванием, масштаб меняется колесом и кнопками «+ − ⤢»; двойной клик возвращает общий вид. Список доступен с клавиатуры: Tab, Enter и пробел. Светлая или тёмная тема выбирается по настройке системы, переключатель в шапке сохраняет выбор в браузере.

## Задачи и команды

Откройте доску «ЗАДАЧИ» на стене или вкладку «Задачи» в боковой панели. Выберите папку из недавних проектов, через обзор папок или по полному пути. Задайте исполнителя, модель, уровень рассуждений и доступ, затем опишите задачу.

Демон запустит CLI в выбранной папке. Сотрудник появится в офисе, ответ — в карточке. Кнопка **«Ответить»** продолжает ту же сессию; модель и уровень рассуждений наследуются, доступ выбирается заново. Продолжение доступно и после перезапуска демона, если сохранён идентификатор сессии.

### Поддержка провайдеров

| Провайдер | Наблюдение | Задачи с доски |
|---|---|---|
| Claude Code, включая вкладку Code в Claude Desktop | Локальные транскрипты и сабагенты | `claude`; для фонового запуска может потребоваться отдельный `auth login` |
| Codex CLI / Desktop | Журналы сессий и локальный индекс чатов | `codex exec`; использует локальную авторизацию Codex |
| Antigravity | Локальные журналы, когда приложение их создаёт | Адаптер `agy`; требуется отдельный CLI и вход, проверка на реальной установленной версии ещё нужна |

На Windows демон ищет Claude и Codex в пакетах Desktop, а также в PATH. Доска показывает причину недоступности исполнителя и для Claude — команду входа. Список моделей Claude задан в коде, Codex берётся из локального `models_cache.json`, Antigravity — из вывода `agy models`.

### Доступ к проекту

| Исполнитель | Режим чтения | Режим правок |
|---|---|---|
| Claude | `--permission-mode plan` | `--permission-mode acceptEdits` |
| Codex | Песочница `read-only` | Песочница `workspace-write` |
| Antigravity | `--mode plan` | `--mode accept-edits` |

У Claude и Antigravity режим plan **не является файловой песочницей**: настройки и правила разрешений CLI продолжают действовать. У Codex применяется выбранная песочница и `approval_policy="never"`. Фоновому процессу некому задавать вопросы о разрешениях; операции, требующие недоступного подтверждения, не выполняются.

Одновременно выполняется не больше **4 задач**. В одной папке допускается не больше одной задачи с правом записи. История задач хранится в `~/.land/tasks.json`.

### Совместная работа

Включите «Совместную работу», выберите исполнителя, планировщика и проверяющего с их моделями и уровнями рассуждений. Можно сочетать разных провайдеров, если их CLI доступны.

1. Планировщик составляет план для выбранного пользователем состава команды.
2. Исполнитель выполняет задачу с выбранным доступом.
3. Проверяющий оценивает результат в режиме чтения.
4. Исполнитель завершает работу с учётом замечаний, по возможности продолжая свою исходную сессию.

Ходы идут последовательно, каждый — отдельный запуск CLI. Коллегам передаётся раздел `## Коллеге` из ответа предыдущего агента, до 3000 символов; он помечается как данные, а не инструкции. Планировщик и проверяющий получают режим чтения с ограничениями соответствующего провайдера.

В «Переговорке» видны участники, порядок ходов, переданные сообщения, итог или причина остановки. Кнопка «Остановить команду» отменяет текущий ход и предотвращает следующий. История последних 30 команд хранится в `~/.land/teams.json`; незавершённая команда после перезапуска демона помечается как остановленная и автоматически не продолжается.

## Как это устроено

```text
Локальные журналы Claude / Codex / Antigravity
                     ↓
          Адаптеры → общее состояние
                     ↓
         Node.js-демон · 127.0.0.1:4317
                     ↕ WebSocket
         PixiJS-офис · 127.0.0.1:5173
                     ↓ задачи с доски
              Демон → CLI агента
```

Демон опрашивает локальные файлы, читает дописанные записи и приводит события к общему протоколу. Интерфейс получает обновления по WebSocket.

| Источник | Путь по умолчанию |
|---|---|
| Claude Code | `~/.claude/projects/<project>/<session>.jsonl`, сабагенты в `<session>/subagents/` |
| Codex | `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`, индекс `~/.codex/state_*.sqlite` |
| Antigravity | `~/.gemini/antigravity/brain/<session>/.system_generated/logs/transcript.jsonl`, метаданные `conversation_summaries.db` |

### Локальные данные и доступ

Демон слушает только `127.0.0.1`, проверяет заголовок `Host` и разрешённые браузерные `Origin`. По умолчанию разрешены `http://127.0.0.1:5173` и `http://localhost:5173`. Для другого адреса клиента задайте `LAND_ALLOWED_ORIGINS` — полные origin через запятую. WebSocket требует разрешённый `Origin`; локальные HTTP-запросы без `Origin`, например хуки и `curl`, также допускаются.

Наблюдение обрабатывает локальные журналы без отправки их в отдельный облачный сервис land.inc. Задачи с доски обращаются к провайдерам через их CLI. Журналы могут содержать промпты, ответы, команды и пути к проектам — учитывайте это при демонстрации экрана коллегам.

### Мгновенные статусы Claude Code — опционально

Без хуков часть ожиданий определяется эвристикой: инструмент не вернул результат больше 12 секунд. Хук `Notification` позволяет сразу показать запрос разрешения или ответа. Добавьте запись в существующие настройки `~/.claude/settings.json`, сохранив остальные настройки и хуки:

```json
{
  "hooks": {
    "Notification": [
      { "hooks": [{ "type": "command", "command": "curl -s -m 1 -X POST --data-binary @- http://127.0.0.1:4317/hook || true" }] }
    ]
  }
}
```

Тот же endpoint понимает `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure` и `Stop`.

## Ограничения прототипа

- Форматы журналов и CLI принадлежат сторонним приложениям и могут меняться. Статусы отражают доступные события; часть переходов определяется эвристиками.
- Antigravity зависит от наличия и обновления внутренних журналов. Модель и ожидание подтверждения достоверно определяются не всегда; связь запущенной задачи с сессией Desktop зависит от версии. Адаптер запуска покрыт тестами с фейковым CLI, полноценная проверка с реальным `agy` остаётся открытой.
- Импортированные в Codex Desktop чаты скрываются, пока в них не появится новая работа в Codex.
- Проект рассчитан на локальную работу. Общий сервер для команды, учёт пользователей и удалённый доступ не реализованы.
- Упаковка в настольное приложение, статистика токенов и стоимости, редактор офиса и системные уведомления — возможные следующие шаги, а не текущие функции.

## Разработка

Стек: **TypeScript · Node.js · WebSocket · PixiJS · Vite**, монорепозиторий на npm workspaces. Демон запускает TypeScript напрямую, без сборки.

```text
apps/daemon/          Наблюдение за сессиями, запуск задач и WebSocket-сервер
  src/adapters/      Разбор локальных журналов провайдеров
  src/executors/     Поиск CLI, параметры запуска и разбор результата
  src/store.ts       Состояния сотрудников и переходы по времени
  src/tasks.ts       Доска задач, доступ, отмена и история
  src/team.ts        Последовательная координация команды
  test/fakes/        Фейковые CLI для проверок без моделей
apps/office/          Изометрическая сцена и рабочие панели
packages/protocol/    Общие типы сообщений и состояний
scripts/dev.mjs       Совместный запуск демона и клиента
```

```bash
npm test             # тесты демона, включая запуск фейковых CLI
npm run typecheck    # проверка TypeScript демона и клиента
npm run build        # сборка веб-клиента
```

Тесты не вызывают модели. Для проверки поведения реального провайдера нужны его установленный CLI и авторизация.
