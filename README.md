# land.inc

2.5D офис для AI-агентов (вид сверху). Агенты ходят по офису, сидят за компьютерами, общаются друг с другом,
а офис живёт синхронно с реальными сессиями **Claude Code / Claude Desktop**, **Codex** и **Antigravity**, которые запущены на этом компьютере.

Никаких API-ключей: офис только читает локальные файлы, которые агенты и так пишут на диск.

## Запуск

Нужен Node.js 24+ (демон запускается из TypeScript без сборки).

В Windows можно дважды щёлкнуть `Открыть офис.cmd`: при первом запуске он установит зависимости, откроет браузер и запустит офис. Оставьте открытым окно запуска; для остановки нажмите в нём Ctrl+C.

```bash
npm install
npm run dev        # демон + офис → http://127.0.0.1:5173
npm run dev:demo   # то же самое плюс демо-агенты, которые проходят по всем зонам
npm test           # тесты; агенты в них — фейковые CLI, ни одна модель не вызывается
```

## Как работает синхронизация

| Источник | Где лежит | Что даёт |
|---|---|---|
| Claude Code (CLI, IDE, вкладка Code в Claude Desktop) | `~/.claude/projects/<project>/<session>.jsonl`, сабагенты в `<session>/subagents/*.jsonl` | Транскрипт в реальном времени: промпты, ответы, вызовы инструментов, `stop_reason` |
| Codex (CLI и Codex Desktop) | `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` + индекс тредов в `~/.codex/state_*.sqlite` | Сообщения, вызовы команд, `task_complete`, запросы разрешений |
| Antigravity | `~/.gemini/antigravity/brain/` и `conversation_summaries.db` | Действия из локальных журналов, доступные сведения о проекте и родителе |
| Хуки Claude Code (опционально) | `~/.claude/settings.json` | Мгновенный сигнал «ждёт вашего разрешения» (`Notification`) |

`apps/daemon` опрашивает эти файлы, читает только дописанные байты и превращает записи в общий поток событий
(`packages/protocol`). Клиент `apps/office` получает его по `ws://127.0.0.1:4317`.

Демон слушает только loopback, принимает запросы только с `Host: 127.0.0.1:<порт>` (защита от DNS rebinding)
и пускает браузер только с разрешённых `Origin`, чтобы посторонний сайт не мог прочитать транскрипты.

По умолчанию браузерный доступ разрешён с `http://127.0.0.1:5173` и `http://localhost:5173`. Для другого адреса
клиента задайте демону `LAND_ALLOWED_ORIGINS` — список полных origin через запятую. Доверяйте только приложениям,
которые должны иметь доступ к журналам. Локальные процессы без `Origin` (хуки, `curl`) могут обращаться к HTTP API;
WebSocket всегда требует разрешённый `Origin`.

Треды, которые Codex Desktop импортировал из других агентов, скрываются: такой файл записан целиком за миллисекунды.
Если продолжить импортированный тред в Codex, его агент появится в офисе.

### Хуки для мгновенных статусов (опционально)

Без хуков «ждёт разрешения» определяется эвристикой: вызов инструмента висит дольше 12 секунд без результата.
С хуком Claude сразу сообщает об этом офису. Добавьте в `~/.claude/settings.json`:

```json
{
  "hooks": {
    "Notification": [
      { "hooks": [{ "type": "command", "command": "curl -s -m 1 -X POST --data-binary @- http://127.0.0.1:4317/hook || true" }] }
    ]
  }
}
```

Демон также понимает `UserPromptSubmit`, `PreToolUse`, `PostToolUse` и `Stop` на том же адресе.

## Что видно в офисе

- **Сессия = сотрудник.** Цвет рубашки: оранжевый у Claude, зелёный у Codex, фиолетовый у демо-агентов.
  Сабагенты поменьше и связаны с родителем пунктиром.
- **Модель = персонаж.** Модель берётся из каждой записи транскрипта (`message.model` у Claude,
  `turn_context.model` и `effort` у Codex), поэтому смена модели посреди сессии тоже видна. На табличке
  указаны модель и уровень рассуждений, например «Sonnet 5.5 · medium».

| Модель | Персонаж |
|---|---|
| Opus | корона и фиолетовый плащ |
| Sonnet | берет и шарф |
| Haiku | поменьше, росток на макушке |
| Fable | синий колпак со звездой |
| GPT Sol | карандаш за ухом, блокнот, значок-солнце |
| GPT Terra | бандана и рабочий фартук |
| GPT Luna | ночной колпак с луной |
| GPT Astra | антенна со звездой |
| Codex Auto Review | маленький инспектор с лупой: служебная проверка, а не отдельный работник |
| Antigravity | парит над полом, вокруг головы орбита со спутником; модель не угадывается, если журнал её не называет |

- **Эмоции.** Ярость печати при правках, круглые очки в архиве, пот и «!» при ожидании разрешения,
  лампочка над головой, если команда идёт дольше 20 секунд, «zzz» после двух минут на кухне.
  Тёмные очки появляются на полторы минуты после зелёных тестов, слёзы — после красных.
- **Проект = ряд столов.** Сессии одного репозитория садятся рядом.
- **Действие → место:**

| Активность | Инструменты | Где агент |
|---|---|---|
| думает / пишет код | reasoning, `Edit`, `Write`, `apply_patch` | свой стол (монитор синий / зелёный) |
| читает | `Read`, `Grep`, `Glob`, `cat`, `rg`, `git log`… | архив |
| запускает команды | `Bash`, `PowerShell`, `shell` | серверная (стойки мигают) |
| ищет в сети | `WebSearch`, `WebFetch`, браузер | интернет-киоски |
| планирует | `TodoWrite`, `update_plan` | доска планов |
| делегирует | `Agent` / `Task`, `spawn_agent` | переговорка |
| ждёт вас | запрос разрешения, вопрос | свой стол, поднятая рука и «!» |
| закончил ход | `end_turn`, `task_complete` | кухня |

После завершения хода сотрудник через 5 минут без активности выходит на улицу и уходит домой. Незавершённая сессия без активности уходит через 45 минут; выполняющийся инструмент или запрос разрешения имеют более долгий тайм-аут. Клик по агенту или строке в списке показывает журнал
его последних действий. Камера: перетаскивание, колесо мыши или кнопки «+ − ⤢» на сцене, двойной клик возвращает общий вид.
Издали на табличках только иконки, ближе — название, вблизи — ещё модель и уровень рассуждений. Если таблички
накладываются, дальняя сворачивается до иконки; выбранный агент и агент под курсором видны полностью.
Список сотрудников управляется с клавиатуры (Tab, Enter или пробел). Тема — светлая или тёмная по настройке системы;
кнопка в шапке закрепляет нужную в этом браузере.

## Доска задач

Пробковая доска «ЗАДАЧИ» на левой стене или вкладка «📌 Задачи» в боковой панели. Выберите папку проекта
(из недавних сессий или любую другую), исполнителя, модель, уровень рассуждений и доступ, затем опишите задачу.
Демон запустит CLI агента в этой папке. Работник войдёт в офис через дверь со значком 📌, а его ответ появится
в карточке задачи.

| | Claude | Codex |
|---|---|---|
| CLI | `claude.exe` из Claude Desktop (или `claude` в PATH) | `codex.exe` из Store-пакета Codex Desktop (или `codex` в PATH) |
| Модели | Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable 5.1 | из `~/.codex/models_cache.json`, кроме скрытых |
| Только чтение | `-p --permission-mode plan` | `exec --sandbox read-only` |
| Может править | `-p --permission-mode acceptEdits` | `exec --sandbox workspace-write` |

Спросить разрешения в фоновом запуске некому. Поэтому у Claude всё, что требует подтверждения (включая команды
терминала), отклоняется, а Codex запускается с `approval_policy="never"`: всё за пределами песочницы
отклоняется. Одновременно выполняется не больше 4 задач. История хранится в `~/.land/tasks.json`.
Задачи принимаются только по WebSocket от разрешённого `Origin`, а модель и уровень рассуждений
проверяются по списку, прежде чем попасть в командную строку.

Встроенный в Claude Desktop `claude.exe` авторизован только внутри сессий Desktop. Для фоновых задач
войдите один раз сами: доска покажет точную команду вида `& "<путь>claude.exe" auth login`.
Codex использует вход Codex Desktop.

Флажок «Совместная работа Claude и Codex» запускает три последовательных хода: выбранный исполнитель выполняет задачу, второй получает его ответ и помогает с работой, затем первый получает оба сообщения и завершает задачу. Модель и уровень рассуждений второго исполнителя выбираются отдельно под флажком. Все ходы используют выбранный для задачи доступ: при выборе «Может править» оба участника могут изменять файлы. Сообщения и ответы видны в карточках отдельных задач; это новые CLI-сессии, а не подключение к уже открытым чатам. Для работы нужны оба доступных исполнителя и модели. Если ход завершился ошибкой или отменён, передача останавливается. Очередь передачи хранится в памяти демона и не возобновляется после его перезапуска.

### Совместная работа

Галочка «Совместная работа» на доске запускает три последовательных хода: автор выполняет задачу, коллега проверяет,
автор завершает её с учётом замечаний. Каждый ход — отдельный запуск CLI.

- Коллеги (не больше трёх) всегда работают **только на чтение**. Право записи, если оно выбрано, есть только у автора.
- Коллегам передаётся только раздел «## Коллеге» из ответа предыдущего агента (не больше 3000 символов), в кавычках
  как данные: агентам сказано, что это информация, а не инструкции, и что выполнять нужно только задачу пользователя.
  Подделать закрывающую кавычку в своём ответе агент не может.
- В одной папке одновременно работает не больше одной задачи с правом записи, совместной или обычной.
- Команды и их история (последние 30) хранятся в `~/.land/teams.json`. Запущенные CLI завершаются вместе с демоном,
  поэтому после перезапуска команда не продолжается: её карточка и задача помечаются как остановленные.

Ход команды виден во вкладке **«Переговорка»**: одна карточка на команду с ходами по порядку (автор, рецензенты,
итог), кто из них работает, кто ждёт, что каждый передал дальше, итог или причина остановки. Кнопка «Остановить
команду» отменяет текущий ход, и следующий уже не начинается. На карте агент, передавший ход, на 20 секунд уходит
в переговорную с облачком «Передаю коллеге: …», а агентов соседних ходов связывает зелёная линия.

Чтобы поработать над интерфейсом без моделей, запустите демон с `--fake-agents`: задачи выполняют фейковые CLI
из `apps/daemon/test/fakes` с задержкой `FAKE_DELAY_MS` (по умолчанию 6 секунд), их работники появляются в офисе,
а история не сохраняется.

Подтверждённый ненулевой код завершения команды может вызвать короткий пожар у стола исполнителя. Нажмите на огонь, чтобы потушить его; он погаснет и сам. Это игровая индикация, а не изменение результата команды.

## Структура

```
apps/daemon        # наблюдатель за файлами + WebSocket-сервер (Node, TypeScript без сборки)
  src/adapters/    # claude.ts, codex.ts, antigravity.ts — наблюдение: разбор транскриптов каждого агента
  src/executors/   # claude.ts, codex.ts — запуск: где CLI, какие модели, командная строка, разбор ответа
  src/store.ts     # состояние агентов и переходы по времени (простой, ожидание, уход)
  src/tasks.ts     # доска задач: проверка, лимиты, блокировка записи, отмена, история
  src/team.ts      # совместная работа: ходы автора и коллег
  test/fakes/      # фейковые claude и codex на node для сквозных тестов
apps/office        # клиент на PixiJS: изометрическая сцена, агенты, боковая панель
  src/character.ts # персонажи по моделям и их эмоции
  src/board.ts     # панель доски задач
packages/protocol  # общие типы событий
```

### Antigravity

Демон наблюдает за `~/.gemini/antigravity/brain/<сессия>/.system_generated/logs/transcript.jsonl`, если такой журнал существует и изменялся за последние 45 минут. Папка проекта и родительская сессия берутся из `conversation_summaries.db`, когда эти сведения доступны; рабочий каталог также может быть указан в контексте запроса. Это внутренние форматы Antigravity: наличие журнала и оперативность обновления зависят от версии приложения. Модель и ожидание подтверждения достоверно не определяются. Ответ без вызовов инструментов считается концом хода по эвристике. Постановка задач из офиса для Antigravity не поддерживается: Antigravity в офисе только наблюдается. land.inc запускает агентов только через их официальные CLI и не использует изменённые бинарники или недокументированные управляющие интерфейсы; вопрос можно вернуть, когда у Antigravity появится поддерживаемый способ запуска. Для проверки откройте новую сессию Antigravity, отправьте задачу и убедитесь, что журнал обновляется и сотрудник появляется в офисе.
